# Installation Guide

> 💡 **Main path: extract and run.** The Server portable package bundles Python 3.12 and every runtime dependency. Normal users do **not** need Python, uv or conda.

## Step 0: Prepare Zotero

- **Zotero**: Zotero 7, Zotero 8, [Zotero 9](https://www.zotero.org/download/) and Zotero 10 are supported. If the in-app update fails, download the latest plugin file and install it again.
- **Python / uv / conda: not required.** The `server.zip` below is a portable package that already contains the Python 3.12 runtime and dependencies such as `pdf2zh`.
- You only need a local Python environment when:
  - you want the `pdf2zh_next` engine (it is **not** bundled) → see [Advanced: run from source (uv/conda)](#advanced-run-from-source-uvconda);
  - you are developing/debugging the Server, or using a non-portable package → see the same section.

## Step 1: Download and extract the portable package

1. Download `server.zip` from **Releases**. Do not use the stale `server.zip` on the repository `main` branch, and do not use source archives (`repository/archive/*.zip`, which often return an HTML login/verification page):

   ```text
   https://github.com/BluesilveEmperor/PDFTranslate-Zotero/releases/latest/download/server.zip
   ```

2. Extract it into an **empty folder**, preferably on a non-system drive, for example `D:\zotero-pdf2zh\server`:

   - **Windows**: right-click `server.zip` → **Extract All…** → choose the target folder;
   - **macOS / Linux**:
     ```shell
     mkdir -p ~/zotero-pdf2zh/server
     unzip server.zip -d ~/zotero-pdf2zh/server
     ```

> ⚠️ The zip has **no** outer `server/` prefix, so files land directly in the folder you choose. Make sure `start_server.bat` / `start_server.sh`, `server.py`, `runtime/` and `site-packages/` are on the **same level**.
>
> The extracted layout should look like:
>
> ```text
> D:\zotero-pdf2zh\server\
> ├── start_server.bat        # Windows launcher
> ├── start_server.sh         # Linux / macOS launcher
> ├── server.py
> ├── runtime\                 # bundled Python 3.12 (~22MB)
> ├── site-packages\           # all dependencies (~813MB extracted)
> ├── config\
> └── ...
> ```

> 💡 **Extraction takes a while**: `server.zip` is about **296MB** with **21,244** entries; after extraction `site-packages/` is about **813MB** and `runtime/` about **22MB**. Expect roughly **85 seconds** (1–2 minutes depending on the disk). Wait until extraction finishes before launching; do not move or open files during extraction.

**Verify the extraction is complete**:

- Windows: `runtime\python.exe` exists;
- Linux / macOS: `runtime/bin/python3` exists and is executable;
- `site-packages\` is not empty;
- If you end up with `server/server/`, move the inner content up one level before launching.

## Step 2: Start the Server

**Windows (recommended)**

Double-click `start_server.bat`. To pass options, open `cmd` in the package root and run:

```bat
start_server.bat --port 9999
```

**Linux / macOS**

```shell
cd ~/zotero-pdf2zh/server
chmod +x start_server.sh
./start_server.sh
```

The launcher points `PYTHONPATH` at the bundled `site-packages/` and runs `server.py` with the bundled Python. Seeing these lines means the portable runtime is active:

```text
📦 便携模式: 使用内置 Python 运行时
   Python: <package dir>\runtime\python.exe
```

**Verify the service**

- The first cold start takes about **7.8 seconds** to answer `/health` with 200; later warm starts take about **4 seconds**.
- Open `http://127.0.0.1:8890` for the web UI.
- Health check:

  ```shell
  curl http://127.0.0.1:8890/health
  ```

  It returns something like `{"status":"ok",...}`.
- Open `/api/config`; `"bundled": true` means the bundled runtime is in use.
- The port follows your `--port` value (default `8890`). The release verification used `--port 8899`; keep the plugin URL on the same port.

> ⚠️ **Important**: translation depends on this process. **Do not close this window** while translating.

### Common parameters

The launcher forwards its arguments to `server.py`, e.g. `start_server.bat --port 9999` or `./start_server.sh --port 9999`:

| Parameter | Description | Default |
|-----------|-------------|---------|
| `--host` | Bind address; localhost only by default. Use `0.0.0.0` only for intentional remote access | `127.0.0.1` |
| `--port` | Server port | `8890` |
| `--check_update` | Check for updates on startup | `True` |
| `--update_source` | Preferred update source (`github` / `gitee`). Both are tried, the other is used on failure | `gitee` |
| `--enable_mirror` | Enable pip mirror acceleration (source / uv / conda mode only) | `True` |
| `--mirror_source` | Custom mirror URL (source / uv / conda mode only) | `https://mirrors.ustc.edu.cn/pypi/simple` |
| `--enable_winexe` | Use the Windows exe mode (requires `--winexe_path`) | `False` |

Examples:

```bat
rem Change the port (remember to update the plugin URL to 9999)
start_server.bat --port 9999

rem Skip the update check to shorten the first start
start_server.bat --check_update=False

rem Allow LAN access (only if you understand the firewall risk)
start_server.bat --host 0.0.0.0
```

```shell
# Linux / macOS forward arguments the same way
./start_server.sh --port 9999
./start_server.sh --check_update=False
./start_server.sh --host 0.0.0.0
```

> 💡 In portable mode `--enable_venv` / `--env_tool` are skipped: dependencies are bundled, so the Server never probes or creates a uv/conda environment.

### Notes

- **The portable package can be moved or renamed as a whole**: it does not depend on uv environment paths. Move `runtime/` and `site-packages/` together with everything else, then double-click the launcher again.
- **Runtime files**: `config/pdf-cache/` (config and cache) and `translated/` (translation products) are created inside the package folder. Keep both when extracting a new package over the old one.
- **Remote Server users**: the Server listens on `127.0.0.1` by default. Add `--host 0.0.0.0` explicitly when other devices must reach it, and configure the firewall/trusted network yourself.

## Portable package notes

| Item | Value / description |
|------|---------------------|
| Download size | about **296MB** (`server.zip`) |
| Extracted size | `site-packages/` about **813MB**, `runtime/` about **22MB** |
| Zip entries | **21,244** |
| Extraction time | about **85 seconds** (typically 1–2 minutes) |
| First cold start to `/health` 200 | about **7.8 seconds** |
| Second warm start | about **4 seconds** |
| Bundled engine | `pdf2zh` fork **1.9.12** |
| Not bundled | `pdf2zh_next` |

- **Bundled runtime**: `runtime/` is the Python 3.12 runtime and `site-packages/` holds all dependencies. The launcher sets `PYTHONPATH` and runs `server.py`; when the Server detects the bundled runtime it skips uv/conda probing and dependency installation.
- **The first real translation still needs the network**: the package does not pre-seed babeldoc model/font assets. The first translation downloads them; on a restricted network it may stall at that step. After the assets are cached locally, later translations reuse them.
- **`pdf2zh_next` is not bundled**: the package only ships `pdf2zh`. To use `pdf2zh_next`, configure an environment via [Advanced: run from source (uv/conda)](#advanced-run-from-source-uvconda) or use the pdf2zh_next standalone exe.
- **Platform-bound**: `runtime/` is platform-specific. Use the official Releases package on the platform it was built for; to run on Linux/macOS, build the package on that platform (the Server code supports `runtime/bin/python3`, but the published package must be built per platform; cross-platform runs have not been verified).
- **Not a Docker package**: Docker deployment remains in [Other installation methods → Docker deployment](#docker-deployment).

## Troubleshooting (portable package)

### `start_server.bat` flashes and closes

1. Open `cmd` in that folder and run `start_server.bat` so you can read the full error (the script also pauses on failure).
2. `[ERROR] runtime\python.exe not found.`: incomplete extraction or wrong folder level. Confirm `runtime\python.exe` sits next to `start_server.bat`; re-extract if needed.
3. `[ERROR] server.py not found.`: you are not in the package root; enter the folder that contains `server.py`.
4. No output at all: check whether antivirus software quarantined `runtime\python.exe` (next item).

### Port already in use

The terminal prints `❌ 端口 8890 已被占用！`. Start on another port and change the plugin URL to the same port:

```bat
start_server.bat --port 9999
```

```shell
./start_server.sh --port 9999
```

You can also change the port in the plugin settings, or stop the program occupying 8890.

### Antivirus interference

Windows Defender, 360 and similar tools may flag `runtime\python.exe` or DLLs under `site-packages\`:

- Add the whole Server folder to the trusted/allowed list and re-extract;
- Do not restore only individual quarantined files; first make sure `runtime/` and `site-packages/` are complete.

### Interrupted extraction / missing files

- If extraction was interrupted, `runtime/` or `site-packages/` may be incomplete; delete the folder and extract again.
- Do not extract only `server.py` or a subset of dependencies; the portable package must be extracted as a whole.
- If you get a `server/server/` nesting, move the inner content up one level.

### The Server starts but translation fails

- Open `/api/config` and confirm `"bundled": true`; if it is `false`, the bundled runtime was not detected (check whether `runtime/` was moved or deleted).
- If the terminal warns that `site-packages/` is missing, the Server still starts but translation fails due to missing dependencies; extract the complete package again.
- If the first translation stalls while downloading or reports `assets download failed`, see "The first real translation still needs the network" above.

## Step 6: Package Updates

**Plugin updates**: use "Check for updates" in Zotero, or enable auto-update.

**Server portable package updates**

- On startup the Server checks GitHub/Gitee (preferring `--update_source`, falling back to the other). When a new version is found the terminal asks for confirmation; answering `y` downloads `server.zip` from Releases and syncs it in place. Restart `start_server.bat` / `start_server.sh` afterwards.
- Manual update: download the new `server.zip` and extract it **over** the existing folder. Keep `config/pdf-cache/` (config and cache) and `translated/` (translation products); replace everything else.
- The bundled `pdf2zh` (fork 1.9.12) updates together with the Server package. No `update_packages.py`, uv or conda is involved.

**Source / uv / conda updates**

`pdf2zh_next` / BabelDOC is a separate translation environment, outside the portable package. When running from source with a managed environment, run this in the `server` folder:

```shell
python update_packages.py
```

It keeps the existing uv/conda environment and installs `pdf2zh_next >= 2.9.0,<3.0.0`. If it is already 2.9.0 or newer, startup no longer asks. Do not create staging / backup environments manually.

On Windows, Conda Python is `<env>\python.exe`; if it cannot be found, `conda run` is used to resolve the real path.

### One-Click Launch Script

> 💡 **Portable package users do not need this**: the package already ships `start_server.bat` (Windows) and `start_server.sh` (Linux/macOS). The manual setup below is only for source-mode users.

You can configure one-click launch for convenience:

**Windows Users - Create Desktop Shortcut Script:**

1. Create a new text file on desktop, edit it with:
```bat
@echo off
cd /d D:\zotero-pdf2zh\server
python server.py
pause
```

2. Save and rename to `start-pdf2zh.bat` (must have `.bat` extension)

3. Double-click to start

**macOS / Linux Users - Configure Alias:**

1. Edit shell config file:
```shell
# If using zsh (macOS default)
nano ~/.zshrc
# If using bash
nano ~/.bashrc
```

2. Add alias at end (modify path as needed):
```shell
alias pdf2zh-start='cd /path/to/zotero-pdf2zh/server && python server.py'
```

3. Save and execute:
```shell
source ~/.zshrc
# or
source ~/.bashrc
```

4. Type `pdf2zh-start` in terminal to launch

# Other Installation Methods

## Advanced: Run from Source (uv/conda)

> Only for developing/debugging the Server, using a non-portable package, or needing the `pdf2zh_next` engine. Normal users should use the portable package above.

**1. Python and source**

- **Python 3.12**: [download](https://www.python.org/downloads/)
- Get the source (skip if you already cloned the repo):

  ```shell
  git clone https://github.com/BluesilveEmperor/PDFTranslate-Zotero.git
  cd PDFTranslate-Zotero/server
  ```

  Or download a source archive from Releases, extract it, and enter the `server` folder.

**2. Choose uv or conda**

**uv (recommended for new users)**

```shell
# macOS / Linux: official installer
wget -qO- https://astral.sh/uv/install.sh | sh
# Windows PowerShell: official installer
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# Verify: a version number means it works
uv --version
```

If the command is not found, add uv to `PATH` and reopen the terminal:

```shell
# macOS / Linux
export PATH="$HOME/.local/bin:$PATH"
# Windows PowerShell
$env:Path = "$env:USERPROFILE\.local\bin;$env:Path"
```

Start the Server (`uv run` prepares the runtime dependencies from `requirements.txt`; the first run downloads them):

```shell
uv run --python 3.12 --with-requirements requirements.txt server.py
```

**conda**

```shell
# Install Miniconda first (see the official guide), then verify
conda --version

# First time only: create a Python 3.12 environment
conda create -n zotero-pdf2zh-server python=3.12 -y
# Activate it
conda activate zotero-pdf2zh-server
# First time only: install Server runtime dependencies
pip install -r requirements.txt
# Start and explicitly use conda
python server.py --env_tool=conda
```

**3. Notes**

- In source mode the Server manages `pdf2zh` / `pdf2zh_next` environments: `--env_tool=auto` reuses an existing uv/conda setup and prefers uv for a fresh one.
- Do not move or rename `server` after installing with uv (environment paths break); conda environments live under `envs/`, so `server` can be moved.
- Update `pdf2zh_next` with `python update_packages.py` in the `server` folder.
- Ports and flags match the portable package (`--port 8890` etc.).

## Windows Standalone exe

Windows users can also use the prebuilt `pdf2zh_next` standalone exe:

1. Download a `pdf2zh-v2.x.x-BabelDOC-v0.x.x-win64.zip` package (`with-assets`) from [pdf2zh_next Releases](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next/releases).
2. Extract it under the `server` folder, keeping the layout `server/pdf2zh-v2.x.x-BabelDOC-v0.x.x-win64/pdf2zh/pdf2zh.exe`.
3. Start the Server:

   ```shell
   python server.py --enable_winexe=True --winexe_path='./pdf2zh-v2.x.x-BabelDOC-v0.x.x-win64/pdf2zh/pdf2zh.exe'
   ```

Notes: the exe does not need a Python virtual environment; the path is relative to `server`. Install the [Visual C++ Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe) if DLL errors appear. If the exe mode misbehaves, prefer the managed environment.

# Frequently Asked Questions (FAQ)

### About Virtual Environment

**Q: uv/conda installation failed, can I skip virtual environment?**

A: If you only use one engine and have Python 3.12.0 globally, you can disable virtual environment management:
```shell
python server.py --enable_venv=False
```

### About Network

**Q: NetworkError when attempting to fetch resource?**

A:
- Ensure plugin is version 1.1.0
- Keep server.py running
- Check if port 8890 is occupied
- Try switching ports
- Check firewall and antivirus

**Q: Translation stuck at certain point?**

A: pdf2zh_next downloads assets on first run. This is slow. You can download the exe package and run once to cache assets.

### About Environment

> 💡 This section covers **source / uv / conda mode**. Portable package users do not create `zotero-pdf2zh-venv` environments; for startup issues see [Troubleshooting (portable package)](#troubleshooting-portable-package).

**Q: DLL initialization routine failed?**

A:
- Downgrade onnx package to version `1.16.1` in virtual environment
- Try installing vs_redist.x86.exe instead of x64
- For macOS old versions, use Python 3.11 instead of 3.12

### About Remote Services

**Q: Can I use without API configuration?**

A: Only free services like siliconflowfree or bing/google work without API.

**Q: Too many tokens consumed?**

A: A 10-page paper typically consumes 70-100k tokens. Try disabling terminology extraction in pdf2zh_next settings.

### About Plugin Features

**Q: Scanned PDF detected, translation failed?**

A: The plugin doesn't provide OCR. Use other tools to OCR your scanned PDF first.

### About Asking Questions

**Q: How to troubleshoot effectively?**

A:
- Read the guide carefully
- Copy terminal output to txt
- Screenshot Zotero settings
- Attach all three to a GitHub Issues report together with what you have checked, methods tried and tutorials watched
